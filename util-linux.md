
| Sub-Category | Purpose & Focus | Core Tools Included | Why it fits your philosophy (or doesn't) |
| :--- | :--- | :--- | :--- |
| **Disk & Partitioning** | Hard drive layout, block device manipulation, and sector-level controls. | `fdisk`, `sfdisk`, `cfdisk`, `partx`, `lsblk`, `blkid`, `wipefs` | **Purely technical.** They exist because they talk directly to the Linux block layer. They are necessary utilities but completely unportable. |
| **Filesystem & Mounts** | Attaching storage devices into the virtual directory tree and managing loop devices. | `mount`, `umount`, `findmnt`, `losetup`, `mountpoint`, `swapon`, `swapoff` | **The core engine.** Essential for Linux system operation. However, modern versions are heavily integrated with `libmount`, which tracks state updates via `systemd`. |
| **Process & IPC Controls** | Fine-tuning execution priorities, scheduling namespaces, and Inter-Process Communication. | `chrt`, `taskset`, `nsenter`, `unshare`, `ionice`, `ipcmk`, `ipcrm`, `ipcs`, `renice` | **Lean kernel hooks.** Excellent choices for a custom base system because they are mostly thin wrappers around Linux syscalls like `sched_setaffinity()` or `unshare()`. |
| **Terminal & Session Management** | Initializing physical or virtual console lines, terminal dimensions, and user login authorization. | `login`, `su`, `agetty`, `runuser`, `setsid`, `wall`, `write`, `mesg` | **High audit risk.** While `agetty` and `setsid` are lean, `login` and `su` are highly problematic for your goals because they are traditionally wired directly into modern Linux PAM and auditing frameworks. |
| **Historical & Text Baggage** | Miscellaneous terminal utilities and text formatters kept alive purely for convenience. | `cal`, `logger`, `whereis`, `look`, `col`, `colcrt`, `colrm`, `rev`, `ul`, `hexdump` | **Unnecessary clutter.** These tools have no real structural reason to be tied to the Linux kernel suite. They are accidental artifacts of 1990s distribution packaging. |
| **System Info & Hardware** | Querying hardware architecture details, kernel rings, and CPU states. | `dmesg`, `lscpu`, `lslogins`, `uname26`, `rfkill`, `chcpu`, `wdctl` | **Information parsers.** They read text streams straight from `/proc` and `/sys`. Most can be replaced entirely by simple shell scripts or direct file reads. |
